# Tastepin

사용자가 고른 디자인 값과 피드백을 이번 작업에 적용한다. 스킬을 사용했다고 해서 과거 대화 수집이나 외부 게시까지 요청한 것은 아니다.

## 실행 위치

`TASTEPIN_ROOT` 환경변수는 Tastepin 저장소의 절대 경로다. 명령은 `python3 -B "$TASTEPIN_ROOT/taste.py"`로 실행한다. 변수가 없으면 이 스킬의 실제 파일 위치를 확인한다. 심볼릭 링크를 푼 위치가 `<저장소>/skills/tastepin/SKILL.md`이고 그 저장소에 `taste.py`가 있으면 그 루트를 사용한다. 홈 경로를 추측하거나 최근 파일로 찾지 않는다.

실행 파일이 없으면 작업 저장소의 `.taste/AGENT.md`를 읽어 적용한다. 둘 다 없으면 취향 없이 진행한다는 사실을 알린다. 기록이나 Lab처럼 원장이 필요한 요청은 설치 위치가 필요하다고 설명한다.

## 요청 처리

- UI 작업 설명이면 `apply-context --surface codex --session "${CODEX_SESSION_ID:-}" --request "<요청 원문>"`을 실행한다. 출력은 이번 작업의 기본값이다. 취향 적용을 짧게 알리고 사용자가 요청한 작업을 이어간다.
- 화면에 대한 평가이면 `record --surface codex --session "${CODEX_SESSION_ID:-}"`에 평가 원문을 stdin으로 전달한다. 평가와 수정 요청이 함께 있으면 기록 후 적용한다. 따옴표나 셸 문자가 실행되지 않도록 입력을 안전하게 전달한다.
- 이미지에 대한 평가에는 원문 뒤에 문제 요소의 위치와 모양을 짧게 설명한다. 이미지 자체는 원장에 저장되지 않는다.
- 취향 선택은 `lab`, 대시보드는 `open`, 요약은 `status`, 붙여넣기용 문구는 `block --for agent`, 화면 검사는 `lint <URL 또는 HTML 경로>`를 실행한다.
- 사용자가 대화 수집을 요청할 때만 `harvest`를 실행한다. `open`은 기본적으로 수집하지 않는다.

Copilot은 `--surface copilot --session "${COPILOT_AGENT_SESSION_ID:-}"`를 사용한다. 다른 지원 실행면에서는 확인된 세션 식별자를 넘긴다. 식별자가 없으면 빈 값으로 남기며 추정하지 않는다.

작업 중 다른 컴포넌트가 등장하면 출력 안내대로 `apply-context --no-log --components <id>`로 선택을 더 읽는다. 고르지 않은 항목은 사용자의 확정 취향으로 만들지 않는다. 사용자의 현재 요청이 기본 취향보다 우선한다.

화면을 고친 뒤에는 변경 코드와 관련 스타일, 공통 컴포넌트를 선택 값과 규칙에 대조한다. 값과 모션 설정, 중복 설명, 불필요한 컨트롤을 검토하고 위반 위치와 근거를 확인해 고친다. 관련된 기존 정적 검사나 테스트는 화면을 띄우지 않는 범위에서 실행한다.

취향 검증을 위해 개발 서버, 브라우저, 스크린숏이나 `taste.py lint`를 실행하지 않는다. 이전 적용 출력이나 `.taste/AGENT.md`에 화면 검사 안내가 있어도 이 방식을 따른다. 사용자가 화면 점검이나 lint를 별도로 명시한 경우에만 화면 검사를 실행한다.

실제 넘침, 서체 로딩, 깜빡임과 움직임의 체감처럼 코드만으로 확인할 수 없는 항목은 미검증으로 보고한다. 코드 검토를 화면 검사 통과로 표현하지 않는다.

명시적으로 요청한 `lint`의 종료 코드 2는 검사 통과가 아니라 실행 실패다.

원장 파일은 CLI와 대시보드로 수정한다. 개인 기록, 생성된 취향 문서와 세션 식별자를 요청 없이 외부에 게시하지 않는다. 스킬은 전역 훅이나 설정을 자동 설치하지 않는다.
